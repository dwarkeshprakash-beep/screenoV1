# /init-agents — Generate Agent Definitions from Project Knowledge

Bootstrap or refresh the senior/junior agent system by reading every MD file and
package.json in the project, then writing fully informed agent definitions to
`.claude/senior/agents/core.md` and `.claude/senior/agents/evolved.md`.

Run this:
- On first setup in any new project
- After major architectural changes
- After adding new tech/integrations
- When /senior feels like it's giving generic advice

The agents it creates will contain project-specific checks, not boilerplate.
They will know your exact tables, your exact bugs, your exact patterns.

---

## PHASE 1 — Read everything

**Read ALL markdown files** in the project (exclude node_modules, .git).
To find them, glob: `**/*.md` from the project root, then read each one.
Priority order (read these first — they have the most context):
1. `BRAIN.md`
2. `CLAUDE.md`
3. `frontend/CLAUDE.md`
4. `backend/CLAUDE.md`
5. `docs/open-issues.md`
6. `docs/rules.md`
7. `docs/database-schema.md`
8. `docs/tech-stack.md`
9. `docs/frontend-guide.md`
10. `docs/backend-guide.md`
11. All remaining `.md` files found

**Read all package manifests:**
- `frontend/package.json` (dependencies + devDependencies)
- `backend/package.json` (dependencies + devDependencies)
- Root `package.json` if present
- Any other manifest: `requirements.txt`, `Cargo.toml`, `go.mod`, `pyproject.toml`, `pom.xml` — if found

**Read key source files for context:**
- `backend/src/routes/` — list all route files
- `backend/src/services/` — list all service files
- `frontend/src/services/api.js` — first 60 lines (to understand API shape)
- `frontend/src/App.jsx` — first 80 lines (to understand route structure)

**Run:**
```
git log --oneline -10
git diff HEAD~1 --stat
```

---

## PHASE 2 — Build project understanding

From everything you read, synthesize these facts. You will use them to write agent definitions.

**A. What the project actually is** (2-3 sentences)
**B. Tech stack** — categorized:
   - Frontend framework + key libraries
   - Backend framework + key libraries
   - Database + driver
   - External APIs / services (LLM, STT, video, email, storage, etc.)
   - Auth mechanism
   - Any unusual patterns (e.g., fetch() instead of SDKs, @param SQL style)

**C. Architecture rules** — what must ALWAYS be true:
   (e.g., SQL only in repositories, no FK constraints, magic-link separate from JWT auth)

**D. Known bugs and open issues** — extract from open-issues.md and BRAIN.md "Current Gaps":
   - List each known data bug, missing feature, or fragmented pattern
   - These become project-specific checks in agent definitions

**E. Security surface** — what are the real auth/access risks for this specific app?
   (e.g., candidate magic-link vs manager JWT, tenant isolation per company_id, exam answer exposure)

**F. Data relationships** — what are the tricky ID namespace issues, JOIN requirements?
   (e.g., team_members.id ≠ candidates.id, scorecard LEFT JOIN required for scores)

**G. Recurring patterns that get violated** — what do you see in open-issues.md repeatedly?
   (e.g., hardcoded hex colors, local Avatar copies, direct fetch() in components, wrong field names)

## PHASE 4 — Write evolved.md

Write `.claude/senior/agents/evolved.md` with this structure.
For EACH distinct technology found in Phase 2 (not the generic frameworks — the specific integrations):
create a Senior and Junior agent definition.

"Distinct technology" means: a specific external API, library, or integration that has its own
failure modes. Examples: LiveKit, Groq, Gemini, Piston, Supabase Storage, JWT auth, LLM prompting,
PDF processing, WebRTC, Redis (if present), etc.

Generic frameworks (React, Express, PostgreSQL) are already covered in core.md — do NOT duplicate them here.

```markdown
# Evolved Agent Registry
Generated by /init-agents on [today's date]
Technologies detected: [comma-separated list of all packages]
Regenerate with: /init-agents

---

[For each distinct integration technology:]

## Senior [Technology] Expert
Added: [today's date]
Source package: [exact package name from package.json]
Trigger files: [specific files in THIS project that use this technology]
Analysis focus:
- [How this technology is used in THIS project specifically]
- [Common failure modes for this tech in this context]
- [Security concerns specific to this tech]
- [Performance considerations]
- [What has already gone wrong with this tech — from BRAIN.md / open-issues.md]
- [What's deferred that relates to this tech]

## Junior [Technology] Reviewer
Added: [today's date]
Trigger files: [same as senior]
Quick checks:
- [3 fast things to verify — the most likely things to go wrong]
```
